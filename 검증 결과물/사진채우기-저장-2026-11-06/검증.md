# 사진 채우기와 첫 문장 이동 분석 · 2026-11-06

## 결론

첨부 JPG에서 보이는 현상과 일치하는 문장 이동을 재구성해 Chromium·WebKit·Firefox에서 재현했다. 원본 프로젝트 설정을 받지는 않았으므로 첨부 화면의 서명·정렬 설정까지 확정한 것은 아니다. 다만 코드의 실제 결함과 동일한 전후 PNG를 확인했다.

원인은 사진의 object-fit이나 아이폰의 폰트 자체가 아니라 **미리보기와 저장의 페이지/단 높이 예약 불일치**다.

- 미리보기 renderPageMarks는 헤더와 서명 높이·간격을 뺀 `hold`를 pageRanges에 넘긴다.
- 위 정렬의 한 장에서는 서명이 흐름에 남는다. 하단에 고정하지 않아 `footHold`는 0이다.
- 저장은 pageRanges()를 다시 부르는데, 기존 기본값은 `headHold + footHold`였다. 서명 높이가 빠져 저장에서만 본문 예산이 커졌다.
- 채우기 사진은 이미 서명 자리를 뺀 높이다. 늘어난 예산에 짧은 첫 문장이 들어간다고 판단하면서 사진 아래에 같은 단으로 넣고, 다음 문단부터 오른쪽 단으로 넘긴다.

재현값(논리 px): 사진 x=30, y=90, h=565. 첫 문장 미리보기 x=212, y=90 → 수정 전 저장 x=30, y=675 → 수정 후 저장 x=212, y=90. 이미지 아래쪽과 서명 사이에 첫 문장이 들어가던 현상이다.

## 해결과 영향 범위

`index.html`에 메모리 변수 `pageRangeHold`를 추가해 미리보기에서 확정한 분할 예약값을 저장에서도 쓴다. renderPageMarks 시작 때 초기화하며 실제 hold 계산 직후 갱신한다.

pageRanges의 기본값을 쓰는 앱 호출부는 저장 한 곳이다. 긴 글 분할과 미리보기는 기존처럼 명시적인 hold를 전달한다. 사진 크롭·object-fit·폰트 임베드·말풍선 크기·CSS·프로젝트 데이터 형식은 바꾸지 않았다. 매번 렌더링에서 갱신하므로 테마/서명 변경에 이전 값이 남지 않는다.

기존 저장이 서명 공간까지 본문에 써서 한 장에 억지로 넣던 경우에는 저장 페이지 수가 달라질 수 있다. 미리보기의 분할과 일치시키는 의도된 변화다. 내용 맞춤은 저장에서 pageRanges를 호출하지 않아 이 변경의 대상이 아니다. 하단 고정 여부를 전부 바꾸는 해결은 서명의 미리보기 위치까지 바꾸므로 채택하지 않았다. 짧은 문장을 무조건 다음 단으로 보내는 예외도 일반 문장 흐름을 바꾸므로 채택하지 않았다.

사진은 헤더·서명·여백을 제외한 본문 칸을 기준으로 채운다. 서명 공간까지 사진을 늘리는 수정은 이번 원인을 해결하지 못하고 서명과 겹칠 수 있어 하지 않았다.

## 확인 결과

`regression.cjs`, `regression.json` 참조.

| 항목 | 검증 |
| --- | --- |
| 엔진 | Chromium, WebKit, Firefox |
| 폰트 | 조선일보명조, 코펍월드돋움, 부크크명조: FontFace 로딩 완료 확인 |
| 정렬 | 위 / 가운데 |
| 서명 | 있음 / 없음 |
| 2단 비율 | 1:1 / 1:2 / 2:1 |
| 사진 순서 | 채우기 사진 뒤 짧은 글 / 짧은 글 뒤 채우기 사진 |
| 규모 | 엔진당 72개, 총 216개 조합 |
| 결과 | 수정 전 높이 예약으로 엔진당 9개 불일치, 수정 후 0개 |
| 실제 저장 | 각 엔진에서 수정 전·후 PNG 생성, 첫 문장 좌표 및 파일 생성 확인 |

WebKit은 iPhone Chrome 형태의 UA로 iOS 저장 분기도 실행했다. 데스크톱의 실제 세 엔진을 사용한 자동화이며, 아이폰 실기·Windows 실기를 직접 사용한 결과는 아니다. 외부 웹폰트 전체, 모든 한글 글리프, 모든 OS 버전을 검증한 것도 아니다. 폰트별 높이가 발동 문턱을 바꿀 수 있으나 확인한 직접 원인은 공통 분할 계산이다.

`*-before.png`와 `*-fixed.png`가 전후 저장 이미지다. 수정 전 출력은 테스트에서 pageRanges의 기본 예약값만 이전 방식으로 돌려 생성했다. 실행 스크립트의 Playwright 경로와 localhost:8774는 이 작업 환경 기준이다.

## 실기 후속 확인

아이폰 Chrome/Safari에서 원래 작업으로 저장해 첫 문장이 오른쪽 상단에 남는지, 사진 하단에 글이 들어가지 않는지 확인한다. 원본 설정에서 서명이 없거나 가운데 정렬인데도 같은 현상이 남으면 이번 재현 조건과 다르므로 그 작업의 설정과 전체 저장 PNG를 기준으로 추가 분석한다. 현재 수정은 로컬에만 적용했으며 배포하지 않았다.
