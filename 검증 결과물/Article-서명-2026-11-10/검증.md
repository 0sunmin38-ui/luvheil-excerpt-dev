# Article 2단·서명 간격 검증 (2026-11-10)

## 변경

- Article 제목 배치를 테마 설정에서 `페이지 전체`(기본) / `단 안`으로 선택한다. 페이지 전체는 내용 맞춤 균등 2단에서 CSS `column-span:all`, 비율 지정 2단에서 페이지별 고정 헤더와 본문 높이 예약을 사용한다. 단 안은 기존 흐름이다.
- 일반 서명은 기존의 페이지 바닥 배치를 유지한다. Instagram DM에서는 서명과 입력창 사이를 테마 아래 여백으로 통일했다.
- 제목 배치는 `paperPlacement`로 테마에 저장된다. 속성이 없는 기존 테마는 페이지 전체로 해석한다.

## 실제 검사

`./serve.sh 8775`에서 `audit.cjs`, `signature.cjs`를 실행했다. 모바일 390×844 뷰포트의 Playwright Chromium, 설치된 Google Chrome, WebKit을 사용했다. Edge 앱은 이 Mac에 설치되지 않아 별도 실기 검증은 하지 않았다. WebKit은 Safari 엔진 검증이며 실제 iPhone Safari는 아니다.

`audit.cjs`는 각 엔진에서 Article 내용 맞춤/비율 지정, 페이지 전체/단 안, 균등/비대칭 2단, 위/가운데 정렬, 3장 출력을 검증했다. 실제 `exportPNG()`를 호출해 PNG data URL, 장 수, 저장 캡처 시 제목 텍스트/폭/중복 수를 확인했다. 페이지 전체의 제목 폭은 496px(본문 전체 폭), 단 안은 236px(한 단 폭)이었다. 비율 지정 비대칭 2단의 3장 모두 제목이 한 번씩 들어갔다. `*-article-page.png`는 해당 저장 PNG 첫 장, `*-article-column.png`는 단 안 내용 맞춤 저장 PNG다. Chromium/WebKit 출력 이미지를 직접 열어 제목과 본문이 겹치지 않음을 확인했다.

테마의 새 속성 `paperPlacement`를 `save()`로 localStorage에 저장하고 새로고침한 뒤 같은 값으로 복원되는 것도 세 엔진에서 확인했다.

`signature.cjs`는 Chromium/WebKit에서 일반 서명의 기존 페이지 바닥 배치를 1/2단, 한/여러 장, 위/가운데 정렬, Kakaotalk/iMessage/Instagram DM 조합으로 실제 저장했다. 짧은 본문과 서명 사이에는 페이지에 남는 높이가 들어간다. 모든 저장 결과는 PNG data URL이며 각 장에 서명이 한 번만 있다.

`decoration-roles.cjs`는 Article·Instagram DM의 독립 사용과 Cyworld/Buddybuddy 프레임에 오래된 Article·Instagram 헤더 값이 남은 중첩 사용을 Chromium/WebKit에서 확인했다. 숨겨진 헤더의 서명 자리나 입력창이 프레임에 영향을 주지 않고, 다섯 조합 모두 실제 PNG로 저장됐다. 결과는 `decoration-roles.json`에 있다.

`margins.cjs`는 8개 장식에서 테마 네 여백을 20px과 60px으로 바꿔 헤더/프레임 외곽, 내부 내용, 첫 본문 좌표, 계산된 패딩을 Chromium/WebKit에서 측정했다. 결과는 `margins.json`, 해석은 저장소의 `장식-구조-비교-및-정리제안-2026-11-10.md`에 있다. 이 단계는 좌표 감사이며, 기존의 PNG 검증과는 별개다.

`signature-margins.cjs`는 같은 두 여백 값에서 없음/iMessage/Instagram DM/Article/Cyworld/Buddybuddy의 실제 서명 좌표를 양쪽 엔진에서 측정했다. 결과는 `signature-margins.json`이다. 역할 판단을 `decorationLayout()`으로 모은 뒤에도 Article·서명·중첩 장식 PNG 검증 스크립트를 재실행해 모두 통과했다.

`dm-spacing.cjs`는 Chromium/WebKit에서 Instagram DM의 자동 높이/비율, 1/2단, 서명 유무 8조합씩을 실제 PNG로 저장했다. 서명이 있을 때 입력창과의 간격은 모든 조합의 미리보기와 저장 캡처에서 테마 아래 여백 60px과 같았다. 서명 없이 자동 높이 2단은 단 균형 배치 때문에 본문과 입력창 사이에 60px보다 큰 빈 공간이 남을 수 있다. 결과는 `dm-spacing.json`이다.

`pagination-observation.cjs`는 고정 비율 3:4, 560px 캔버스에서 6줄짜리 일반 글 블록 8개가 이어지는 상황을 Chromium/WebKit에서 측정했다. 블록 하나의 높이는 171px이고 블록 간격은 20px이다. 변경 전에는 첫 장에서 서명 없이 130px, 서명이 있으면 82px이 남아도 다음 블록 전체를 넘겼다. 변경 후에는 현재 장에 들어가는 분량을 먼저 채워 첫 장의 남는 공간이 각각 24px과 5px으로 줄었다. 두 엔진의 측정 결과는 같다. 결과는 `pagination-observation.json`이다.

`pagination-fill.cjs`는 1/2단, 서명 유무, 4/5/6줄 블록의 12조합을 Chromium/WebKit에서 실제 PNG로 저장했다. 블록의 원문이 유지되고, 저장 캡처의 페이지별 본문을 이어 붙인 결과도 원문과 일치했다. PNG 장 수와 서명 수는 미리보기와 같았다. 남은 공간에 한 줄만 들어가도 분할한다. 실제 샘플에서는 서명 없는 5줄 블록이 1줄·4줄로, 서명 있는 4줄 블록이 3줄·1줄로 나뉘었다. 한 줄도 들어가지 않는 5줄 사례는 다음 장으로 옮겼다. 1단의 끝 페이지를 제외한 남는 높이는 최대 33px으로, 이 샘플의 한 줄 높이와 블록 간격의 합(약 49px)보다 작았다. 결과는 `pagination-fill.json`이다. 기존 `긴서술-2026-10-13`의 장문·비대칭 2단·Article·하단 장식 PNG 검증도 새 정책에 맞춰 다시 통과했다.

자동화가 검사한 것은 이 브라우저 엔진과 샘플 조합이다. Edge 실기, iPhone Safari 및 iOS Chrome, Android Chrome의 실제 공유/다운로드 동작은 별도 기기 검증이 필요하다.
