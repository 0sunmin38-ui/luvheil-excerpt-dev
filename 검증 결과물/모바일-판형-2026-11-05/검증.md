# 모바일 읽기 판형 첫 구현 검증

기준: 2026-11-05. `index.html`에 새 `모바일 읽기` 프리셋을 추가하고, 비율 지정 캔버스에 선택적 `shortSide` 값을 도입했다. 기존 테마에 이 값이 없으면 논리 짧은 변 560px을 사용한다.

## 적용값

| 항목 | 모바일 읽기 시안 |
| --- | --- |
| 기본 판형 | 3:4, 400×533px |
| 다른 세로 판형 | 1:1 400×400px, 9:16 400×711px |
| 본문 | 18px, 행간 1.6 |
| 화자 이름 | 본문에 연동하되 최소 13px |
| 헤더·서명 | 각각 14px·12px로 본문 크기와 분리 |
| 말풍선 | 안쪽 10px/13px, 같은 화자 연속 간격 7px |
| 바깥 여백 | 위아래 24px, 좌우 22px |
| PNG | 기존의 짧은 변 약 1440px 목표 유지 |

4:5 캔버스는 추가하지 않았다. 본문 이미지의 `원본` 비율 선택도 유지했다.

## 자동 검사

검사 파일: `check.cjs`, `regression.cjs`, `audit.cjs`. 로컬 서버에서 Chromium과 WebKit을 320·360·390px 모바일 뷰포트와 1440px 데스크톱 뷰포트로 실행했다. 계획 대비 누락과 위험은 [후속 점검](계획-대비-후속점검.md)에 기록했다.

- 3:4·9:16·1:1의 논리 크기가 위 표와 일치했다. 모바일 미리보기는 0.895배로 축소됐고, 논리 줄바꿈은 데스크톱과 같았다.
- 본문을 14·18·22px로 바꿔도 새 모바일 시안의 헤더 12px, 서명 12px이 유지됐다. 이름은 각각 13·14.4·17.6px이었다.
- 3:4 PNG는 1440×1918px이었다. 논리 높이를 정수 533px로 반올림한 결과여서 정확한 수학적 3:4인 1440×1920px과 2px 차이가 난다. 샘플의 말풍선과 본문 줄바꿈은 미리보기·PNG가 같았다.
- 9개 대화 블록은 3쪽으로 나뉘고 PNG 3장으로 저장됐다. 블록 순서와 원문이 저장 전후에 유지됐고 페이지 오버플로 표시는 없었다.
- v21 저장본을 불러오면 새 프리셋 1개가 더해졌다. 직접 조정한 기존 테마의 본문 17px, 왼쪽 여백 37px, 판형 560px, 활성 선택이 유지됐다. 새 모바일·Bubble 프리셋의 본문은 13px이고 저장 버전은 24이다.
- 내용 맞춤 430px, Cyworld 4:3·747px, 기존 설정 JSON 병합 가져오기의 560px 호환값을 확인했다.
- 본문 이미지 `원본`은 240×480 및 480×240 SVG를 자르지 않고 각각 1:2와 2:1로 배치했으며 PNG 저장이 완료됐다.
- 기존 카카오의 헤더가 본문 14→22px을 따라 커지던 상태를 재현한 뒤, 판형 기준 고정으로 수정했다. 560px 판형에서는 헤더 글자 기준 20px·최소 높이 약 91px을 쓰며, 본문을 바꿔도 제목·아이콘·높이가 같다. 기존 인스타 DM도 같은 규칙을 쓴다.
- 사용자가 제공한 1170×1560px 3:4 캡처 두 장의 상단부 비중을 400px 판형으로 환산해 헤더 64px을 기준으로 삼았다. 비율·공간 배치만 참고했고 원본 앱의 장식 모양을 그대로 복제하지 않았다.
- `짧은 변` 스텝퍼를 제거했다. 이전 저장본의 560px과 새 시안의 400px 및 설정 JSON에 명시된 값을 유지한다. 기존에 직접 고른 헤더 크기는 보존하고 판형 기준으로 되돌리는 UI를 확인했다.
- 새 모바일 시안의 헤더를 Instagram DM으로 바꿔도 이름·입력 장식과 음악 카드 제목 크기가 본문 14→22px에서 유지됐다. v22 저장본에는 새 음악 크기 기준만 보충했다.
- Wi‑Fi 테스트 서버는 앱과 번들 웹 글꼴만 제공한다. `.git/config`, `serve.sh`, 인코딩된 상위 경로는 404, 앱과 글꼴은 200이었다.
- 기존 카카오의 긴 대화도 고정 헤더를 적용한 상태에서 3쪽·PNG 3장으로 저장됐고 페이지 오버플로 표시는 없었다.
- iMessage·Kakaotalk·Instagram DM·Bubble·e-Book·Lock Screen·Article의 7종 헤더를 본문과 독립된 글씨 크기로 고정했다. 각 유형의 기본 높이에 30px을 더하고 글씨 기준 16px·SVG 크기 125%를 적용해, 본문 14·22px에서도 헤더 글자·높이·위치가 유지되는지 확인했다. 저장본의 이전 이동값 24px은 무시되어 고정형 헤더가 상단 0px에 놓였다. 7종 모두 Chromium·WebKit에서 PNG 저장을 완료했다.
- 높이·글씨·SVG 크기는 유형별로 저장된다. iMessage에 높이 130px·글씨 기준 18px·SVG 150%를 편집기에서 적용하고 새로고침 후 보존됨을 확인했다. 세 칸 모두 숫자 직접 입력이며 증감 단추와 아래 이동 칸은 없다.
- iMessage 높이를 110→170px로 바꾸면 내용 위아래의 여백이 각각 약 30px 늘고 선은 헤더 하단에 남았다. SVG 100→150%에서 아이콘의 실제 표시 크기도 커졌다. 높이 40px을 입력한 카카오 헤더의 실제 렌더 높이는 40px이었다. 직접 지정한 높이가 내용보다 작으면 넘친 부분은 잘린다.
- 잠금화면 시계 글씨는 헤더 글씨 기준 14→20px에 따라 커졌다. Instagram DM 헤더 글씨 기준을 바꿔도 하단 입력창의 크기 기준은 유지됐다.
- 이전 이동값 24px을 포함한 카카오 높이 120px·3장 대화는 본문 위쪽 120px을 예약했고, 2·3장의 헤더 사본도 각 장의 상단 0px에 놓였다. PNG 3장으로 저장됐으며 오버플로 표시는 없었다.
- 두 엔진 모두 페이지 스크립트 오류가 없었다.

## 헤더 기본 비율·본문 13px 후속 검증

`header-calibration.cjs`를 Chromium·WebKit에서 실행했다. 19개 기본 테마의 본문 크기는 모두 13px이었다. 기존 저장본에서 옛 프리셋 기본 크기를 유지한 테마만 13px로 이동했고, 직접 17px로 바꾼 카카오 테마는 유지됐다.

| 헤더 | 높이 | 글씨 기준 | SVG |
| --- | ---: | ---: | ---: |
| Kakaotalk | 60px | 12px | 90% |
| iMessage | 90px | 12px | 130% |
| Instagram DM | 70px | 12px | 100% |
| Bubble | 80px | 12px | 100% |
| e-Book | 60px | 13px | 100% |
| Lock Screen | 240px | 16px | 해당 없음 |
| Article | 112px | 20px | 해당 없음 |

- 카카오 좌우 패딩은 28px이고 글씨 기준을 20px로 바꿔도 그대로였다. 이름 중심과 캔버스 중심의 차이는 두 엔진에서 0px이었다.
- iMessage 좌우 아이콘은 캔버스 여백과 분리된 좌우 패딩 30px 안쪽에 있었고, 아이콘 세로 중심은 **헤더 전체 영역의 중앙**과 Chromium에서 0.01px, WebKit에서 0.08px 이내로 일치했다. 프로필 이미지는 40px에서 별도 입력으로 50px까지 변경됐다. 하단 선은 헤더의 좌우·바닥 끝에서 0px이었다. 내용 아래 이동 기본값은 4px, 아이콘 선 굵기는 2.4px이며 하단 그림자는 없다.
- [iMessage 저장 PNG](calibrated-imessage-export.png)를 미리보기와 대조해 양끝 아이콘의 중앙 높이, 하단 구분선, 그림자 제거가 저장본에도 유지됨을 확인했다.
- Instagram DM 프로필 링은 글씨 기준 12→20px에서도 바깥 42px·안쪽 38px을 유지했다. 하단 메시지 창의 크기 단위는 0.857→1.319px로 함께 변했다. 링 크기는 별도 입력으로 조정할 수 있다.
- Lock Screen의 날짜 글씨 기본값은 20px, 날짜·시간 간격 기본값은 8px이다. 날짜 글씨만 24px로 바꿔도 시계 크기와 분리된다. 기존에 헤더 수치를 직접 수정한 테마는 `이 헤더에 새 기본값 적용` 단추로 요청 기본값을 적용할 수 있다.
- 일반 대사 프로필은 28→30.8px, 알림형은 42→46.2px, SNS형은 48→52.8px이 됐다. Bubble 테마 프로필은 38px을 유지했다.
- 320·360·390·1440px 화면에서 1:1·3:4·9:16 미리보기와 PNG 검사를 통과했다. 3:4 PNG는 이전과 같이 1440×1918px이다.

비교 파일: [미리보기](preview-3x4.png), [저장 PNG](export-3x4.png), [헤더 높이·이동 시안](header-adjusted-preview.png). 동일 샘플에서 헤더, 말풍선, 서명 위치와 문장 줄바꿈을 육안 대조했다.

## 아직 확인할 환경

iPhone Safari 실기, Galaxy Chrome·Samsung Internet 실기, Windows Chrome·Edge의 글꼴 대체와 OS 배율은 이 환경에서 확인하지 않았다. 자동 검사만으로 실기 완료로 간주하지 않는다. 실제 휴대폰 사진/파일 앱에서 320·360·390px 표시 폭의 가독성, 회전·키보드·확대, Android 직접 캡처와 여러 장 저장을 확인해야 한다. 320px 편집 미리보기의 배율은 0.72라 현재 13px 논리 본문이 약 9.4px로 보인다. PNG를 화면 폭 전체로 열었을 때의 가독성과 구별해서 판단해야 한다.

## 설정 탭 순서

표시·키보드 순서를 `캐릭터 → 서명 → 테마`로 바꾸고, 목록과 편집 화면의 슬라이드 방향도 같은 순서로 맞췄다. 기존 내부 화면 번호와 저장·뒤로가기 연결은 유지한다. `tab-order.cjs`에서 Chromium·WebKit의 390px 모바일 및 1440px 데스크톱 화면을 대상으로 세 탭 클릭, 선택 표시, 목록 가시성, 서명·테마 편집 연결을 확인했다.

## 후속 변경: 장식 고정 및 제공 테마 자동 갱신

위 헤더 조절 결과는 당시 구현 기록이다. 현재는 e-Book 헤더를 제거하고 해당 기본 테마 3종에 Kakaotalk 헤더를 쓴다. 헤더 높이·장식 글씨·SVG·좌우 패딩·프로필 이미지·날짜 크기 등 헤더 치수는 장식 종류별 코드 기본값으로 고정했고 조절 UI를 제거했다. 이전 저장본의 e-Book 헤더는 Kakaotalk으로 바꾸고 이전 헤더 치수 값은 제거한다.

제공 테마는 편집할 수 없으므로 저장본이나 설정 파일의 오래된 제공 테마 값 대신 현재 코드 정의를 자동 적용한다. 테마 ID·목록 순서·활성 선택·직접 만든 테마는 유지한다. 초기화 메뉴에서 테마 프리셋 항목을 제거했다. `header-calibration.cjs`로 Chromium·WebKit 모바일 화면에서 헤더 고정, PNG 생성, 이전 저장본·설정 파일 가져오기, 자동 갱신, 초기화 메뉴를 확인했다. 결과물: [Kakaotalk PNG](header-fixed-kakao.png).

설정 JSON을 내보낼 때 제공 테마 본문은 제외하고 직접 추가·복제한 테마만 담는다. 제공 테마를 선택 중이면 파일의 활성 테마 ID는 `null`로 기록한다. 들여올 때도 예전 파일의 제공 테마는 제외하고 로컬 제공 테마를 유지한다. 덮어쓰기는 직접 만든 테마 목록에만 적용한다. 구버전 파일에서 `presetId`가 남은 ` 사본` 테마는 사용자 테마로 가져온다. Chromium·WebKit에서 JSON 내보내기와 구버전 파일 들여오기를 확인했다.
